CRITICALFix switchIncident & handleLaunchTriageSquad used before declaration
web/src/app/war-room/page.tsx · lines 782, 791

The Problem: The init useEffect (line ~776) calls switchIncident() and handleLaunchTriageSquad() to handle URL params like ?incident=B&autoplay=true. Both functions are declared as const arrow functions after the effect. In JavaScript, const is not hoisted — it causes a Temporal Dead Zone error. The deep-link URL and autoplay URL param are silently broken.

Root Cause: Function declarations were put in logical reading order (effects first, then handlers), but the effect references handlers that aren't yet initialized.

Fix Strategy: Convert the two functions to useCallback hooks and declare them before the useEffect that references them. This also satisfies React's exhaustive-deps rule.

// BEFORE (broken — const is not hoisted):
useEffect(() => {
  const init = async () => {
    ...
    switchIncident(incParam);           // ❌ TDZ — not declared yet
    handleLaunchTriageSquad();          // ❌ TDZ — not declared yet
  };
  init();
}, []);

const switchIncident = (inc) => { ... };        // line 812 — too late!
const handleLaunchTriageSquad = async () => { ... }; // line 996 — too late!

// AFTER (fixed — useCallback placed before the useEffect):
const switchIncident = useCallback((inc) => {
  clearAllTimeouts();
  setSelectedIncident(inc);
  setIsPlaying(false);
  setIsAutopilot(false);
  setAutopilotMsg(null);
  setStep(0);
  setElapsedMs(0);
  setMttrFrozen(null);
  setShowCrownBanner(false);
  setBleedAmount(145.0);
  setDetectives(INCIDENT_DATA[inc].detectives);
  setSelectedCommit(
    INCIDENT_DATA[inc].commits.find((c) => c.type === 'CULPRIT')
    || INCIDENT_DATA[inc].commits[0]
  );
  setLiveTestOutput(null);
  setLiveTestPassed(null);
  checkLiveDiskStatus();
}, []);  // stable ref — no deps needed

// handleLaunchTriageSquad wrapped in useCallback similarly
const handleLaunchTriageSquad = useCallback(async () => {
  ...
}, [isPlaying, step, currentIncident, ...]);  // all deps declared

// THEN the useEffect can safely reference them:
useEffect(() => {
  const init = async () => {
    await checkLiveDiskStatus();
    const params = new URLSearchParams(window.location.search);
    const incParam = params.get('incident');
    if (incParam && ['A','B','C','D'].includes(incParam))
      switchIncident(incParam);          // ✅ works — ref is stable
    if (params.get('autoplay') === 'true') {
      setTimeout(() => handleLaunchTriageSquad(), 700); // ✅ works
    }

  init();
}, [switchIncident, handleLaunchTriageSquad]);  // deps satisfied

SecurityAdd server-side rate limiting to /api/heal POST
web/src/app/api/heal/route.ts

Currently, if DEMO_KEY is not set (default local dev mode), the API accepts unlimited POST requests. Anyone who finds your local IP on a shared network could spam-break your target files. Add a simple in-memory token bucket to cap requests to 10 per minute.

// Add at the top of route.ts, before the handlers:
const requestBucket = { count: 0, resetAt: Date.now() + 60_000 };

function checkRateLimit(): boolean {
  if (Date.now() > requestBucket.resetAt) {
    requestBucket.count = 0;
    requestBucket.resetAt = Date.now() + 60_000;
  }
  requestBucket.count++;
  return requestBucket.count <= 10;  // 10 req/min
}

// In POST handler, after checkAuth:
if (!checkRateLimit()) {
  return NextResponse.json(
    { success: false, error: 'Rate limit exceeded' },
    { status: 429 }
  );
}
🎯 Prevents API abuse on local network ⏱ ~10 min

ArchAdd lib/telemetry.ts — centralize MTTR math & financial calculation formulas

// web/src/lib/telemetry.ts
export const BLEED_RATE_PER_TICK = 1.45;  // $1.45 per 100ms tick
export const BLEED_START_AMOUNT = 145.0; // Initial outage damage already done
export const HUMAN_COST_PER_INCIDENT = 900;  // 3 SREs × 2.5hr × $120/hr
export const BOB_COST_PER_INCIDENT = 0.38; // ~0.38 Bobcoins

export function formatTimer(ms: number): string {
  const totalSecs = Math.floor(ms / 1000);
  return [
    Math.floor(totalSecs / 60).toString().padStart(2, '0'),
    (totalSecs % 60).toString().padStart(2, '0'),
    Math.floor((ms % 1000) / 10).toString().padStart(2, '0'),
  ].join(':');
}

export function calcAnnualSavings(monthlyIncidents: number): number {
  return (
    monthlyIncidents * (HUMAN_COST_PER_INCIDENT - BOB_COST_PER_INCIDENT) * 12
  );
}

ArchFix err: any typed catch blocks — replace with unknown + type guard
api/heal/route.ts:64,247 · war-room/page.tsx:861,893,979,1103 · page.tsx:559,810

ESLint reports 8 instances of catch (err: any). The correct TypeScript pattern for catch blocks is unknown + a type guard.

// BEFORE (unsafe — any can propagate silently):
} catch (err: any) {
  return NextResponse.json({ error: err.message }, { status: 500 });
}

// AFTER (type-safe):
} catch (err: unknown) {
  const msg = err instanceof Error ? err.message : String(err);
  return NextResponse.json({ error: msg }, { status: 500 });
}
